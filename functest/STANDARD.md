# Usuba Standard v0.1: what a working Omarchy plugin is

Target: Omarchy 4.0.4-1 (shell tree byte-identical to basecamp/omarchy@c668141), Quickshell + Qt 6.11 as installed on the reference Dell.

The Usuba Checker (functest/) enforces this standard: static checks (static_checks.py, dell_checks.py, usuba/checks.py), task-contract checks (rescore.py) and a real-shell runtime probe (runtime.py). Every failure the checker emits starts with a rule id from this document and ends with a `Fix:` hint.

Levels: **error** always fails. **high** is a heuristic finding that fails (it is reported as `heuristic/high` so a human can overrule it). **medium**/**low** heuristics are warnings only.

The type and member allowlists (USB-Q01, USB-A01, USB-A02, USB-A04) are generated by `usuba/build_types.py` from the qmltypes/qmldir files of the Qt 6.11 and Quickshell builds the runtime uses and from Omarchy 4.0.4's shell/Commons and shell/Ui, so they move with the Dell rather than with a hand-kept denylist.

## Task contract

### USB-T01: Answer contains plugin code
- Level: error
- Rationale: A manifest alone (or an empty answer) installs nothing that runs; the old grader passed manifest-only answers on chunk tasks because the upstream tree supplied the code.
- Failing example: `### manifest.json only, for "Write a complete Omarchy plugin ..."`
- Fix: return the QML entry point(s) the manifest names, in full
- Checked by: rescore.task_findings

### USB-T02: Requested file is delivered
- Level: error
- Rationale: When a task asks for a specific file, the answer must contain that file with a real implementation.
- Failing example: `"Implement `HomeContent.qml` in full" -> answer contains only manifest.json`
- Fix: return the complete requested file
- Checked by: rescore.task_findings

## Manifest

### USB-M01: manifest.json is valid JSON with an id
- Level: error
- Rationale: Omarchy refuses to register a plugin it cannot parse.
- Failing example: `trailing comma in manifest.json`
- Fix: fix the JSON
- Checked by: static_checks

### USB-M02: Entry points are QML files
- Level: error
- Rationale: Quickshell loads QML only; a .js/.py entry point never loads.
- Failing example: `"entryPoints": {"barWidget": "main.js"}`
- Fix: point entryPoints at .qml files
- Checked by: static_checks

### USB-M03: Plugin ships QML
- Level: error
- Rationale: A plugin with no QML has nothing for the shell to instantiate.
- Failing example: `manifest + tablet.py only`
- Fix: add the QML entry points
- Checked by: static_checks

### USB-M04: Entry root is a shell surface
- Level: error
- Rationale: ApplicationWindow/Window roots open a desktop app window instead of a bar widget/panel/overlay.
- Failing example: `ApplicationWindow { ... } as barWidget`
- Fix: use Item / BarWidget / Panel (qs.Ui) as the root
- Checked by: static_checks

### USB-M05: Namespaced, non-reserved id
- Level: error
- Rationale: Third-party plugins must use a namespaced id outside omarchy.*.
- Failing example: `"id": "time-machine"`
- Fix: use e.g. "jankeesvw.time-machine"
- Checked by: rescore (fix_manifest)

## QML types and imports

### USB-Q01: Every QML type resolves (positive allowlist)
- Level: error
- Rationale: A type that no imported module provides makes the component fail to load. The allowlist is built from the real Qt 6 / Quickshell qmltypes and Omarchy qs.Commons/qs.Ui QML (usuba/types.json), plus the plugin's own QML files, qmldir entries and inline components.
- Failing example: `layer.effect: DropShadow { ... } with only `import QtQuick`; `Process { }` without `import Quickshell.Io``
- Fix: add the import that provides the type, or use a type that exists
- Checked by: usuba/checks.py

### USB-Q02: Imports exist
- Level: error
- Rationale: Importing a module that does not exist (or an Omarchy module other than qs.Commons/qs.Ui) breaks loading.
- Failing example: `import qs.Services`
- Fix: import only Qt 6, Quickshell, qs.Commons, qs.Ui or shipped files
- Checked by: static_checks

### USB-Q03: No Qt 5 APIs
- Level: error
- Rationale: Omarchy runs Qt 6; Qt 5 modules are absent.
- Failing example: `import QtGraphicalEffects 1.15`
- Fix: use Qt5Compat.GraphicalEffects or QtQuick.Effects
- Checked by: static_checks

### USB-Q04: Valid QML structure
- Level: error
- Rationale: QML objects cannot be declared inside JavaScript blocks.
- Failing example: `Component.onCompleted: { Timer { } }`
- Fix: declare objects in QML, start them from JS
- Checked by: static_checks

## APIs

### USB-A01: Only real APIs are called
- Level: error
- Rationale: Invented JS APIs throw at runtime, usually on a click path the smoke test never exercises. Members of `Qt.*` and `Quickshell.*` are checked against the real objects; calls on capitalised names must hit a singleton, JS import or id in scope. A small denylist of observed hallucinations backs this up.
- Failing example: `Quickshell.exec([...]).then(...); Qt.clipboard.text = s; Service.call("x", "y")`
- Fix: use Process / Quickshell.execDetached / omarchy-shell IPC / wl-copy
- Checked by: usuba/checks.py

### USB-A02: Signal handlers name real signals
- Level: error
- Rationale: A handler for a signal the type does not have never fires (or fails to load). Signals come from the type's qmltypes/QML definition plus its prototype chain.
- Failing example: `Process { onFinished: ... }  (Process has exited/started)`
- Fix: use the type's real signal, e.g. onExited, or StdioCollector.onStreamFinished
- Checked by: usuba/checks.py

### USB-A03: QML types are not constructed with `new`
- Level: error
- Rationale: `new SequentialAnimation()` is not valid QML JavaScript.
- Failing example: `var a = new NumberAnimation()`
- Fix: declare the object in QML with an id
- Checked by: usuba/checks.py

### USB-A04: Methods called on ids exist
- Level: error
- Rationale: Calling a method the object's type lacks throws a TypeError.
- Failing example: `proc.start()  // Process has no start()`
- Fix: use the real method/property (running = true)
- Checked by: usuba/checks.py

### USB-A05: No Node/browser/C++ idioms in QML JS
- Level: error
- Rationale: require(), fetch(), document.*, QProcess etc. do not exist in Quickshell.
- Failing example: `const cp = require('child_process')`
- Fix: use Process / XMLHttpRequest
- Checked by: static_checks

### USB-A06: qs.Commons singleton members exist
- Level: error
- Rationale: Color/Style/Util/Border members that the real singleton lacks are undefined.
- Failing example: `Color.accent2`
- Fix: use a member that exists in shell/Commons
- Checked by: dell_checks

## Binaries and commands

### USB-B01: Binaries in shell strings exist on the Dell
- Level: error
- Rationale: `sh -c`/`bash -c` strings, os.system strings and shipped shell scripts are parsed; every command word must be on the Dell's PATH (dell_env/system_bins.txt + omarchy_bins.txt), shipped, or documented as a dependency.
- Failing example: `["sh", "-c", "playerctl status | head -1"]`
- Fix: use an installed tool, ship a script, or document the dependency in README.md
- Checked by: usuba/checks.py

### USB-B02: No X11-only tools
- Level: error
- Rationale: Omarchy is a Wayland/Hyprland session; xinput, setxkbmap, xdotool, onboard, xclip, xrandr ... do nothing or are missing.
- Failing example: `subprocess.run(["setxkbmap", "de"])`
- Fix: use hyprctl / wtype / wl-copy / a Wayland OSK
- Checked by: usuba/checks.py

### USB-B03: hyprctl / hyprsunset invocations are valid
- Level: error
- Rationale: Invented subcommands fail silently.
- Failing example: `hyprctl background add x.png; hyprsunset enable`
- Fix: use real hyprctl commands; hyprsunset -t 4500 / hyprctl hyprsunset temperature 4500
- Checked by: usuba/checks.py

### USB-B04: No hyprctl reload after hyprctl keyword
- Level: error
- Rationale: `hyprctl reload` re-reads hyprland.conf and discards the runtime keywords just applied.
- Failing example: `hyprctl keyword general:gaps_in 4; hyprctl reload`
- Fix: drop the reload
- Checked by: usuba/checks.py

### USB-B05: argv[0] exists on the Dell
- Level: error
- Rationale: A Process whose program is not installed never starts.
- Failing example: `command: ["walker"]`
- Fix: use an installed program or ship/document it
- Checked by: dell_checks

## Shipped files

### USB-F01: Referenced helper scripts are shipped
- Level: error
- Rationale: A command that runs bin/foo.sh or scripts/x.py the plugin does not contain fails at click time.
- Failing example: `command: ["bash", Qt.resolvedUrl("bin/speed.sh")] with no bin/speed.sh`
- Fix: ship the script or inline the command
- Checked by: usuba/checks.py

## JavaScript correctness

### USB-J01: No undeclared identifiers
- Level: error
- Rationale: Assigning or dereferencing a name that is never declared is a ReferenceError; wrapping it in try/catch only hides that the feature shows nothing.
- Failing example: `try { const w = shell.wm.windows } catch (e) {}`
- Fix: declare the property and fill it from a real API
- Checked by: usuba/checks.py

### USB-J02: Commands never receive undefined
- Level: error
- Rationale: argv built from bar.<x>/settings.<x> that do not exist passes the string 'undefined'.
- Failing example: `command: ["x", settings.mode] with no `mode` default`
- Fix: declare manifest defaults / use real PluginBarApi members
- Checked by: dell_checks

## Safety

### USB-S01: No writes to protected paths
- Level: error
- Rationale: Plugins must not modify Hyprland/Omarchy config, /etc, /usr or shell rc files.
- Failing example: `echo ... >> ~/.config/hypr/hyprland.conf`
- Fix: use hyprctl keyword at runtime or the plugin's own data dir
- Checked by: static_checks / runtime

### USB-S02: No privileged or remote-exec commands
- Level: error
- Rationale: sudo/pkexec, curl|sh and rm -rf of home are rejected.
- Failing example: `["pkexec", ...]`
- Fix: do not escalate; document manual steps
- Checked by: static_checks

## Heuristics (graded)

### USB-H01: Real data, not simulated
- Level: high/medium
- Rationale: Code that says its data is simulated/mock/fake is a stub. High (blocking) when the wording is explicit or the plugin has no data source at all; medium otherwise.
- Failing example:

```
// Safe simulation: avoids calling external binaries
status = "Up to date"
```
- Fix: read the real source (Process, FileView, Quickshell service)
- Checked by: usuba/checks.py

### USB-H02: No hardcoded readings shown as live data
- Level: high/medium
- Rationale: A literal like "22°C" or "45%" in a Text is a placeholder. High when the plugin has no IO at all.
- Failing example: `text: "☀️ 22°C"`
- Fix: bind the text to a property filled from a real source
- Checked by: usuba/checks.py

### USB-H03: Handlers do something besides console.log
- Level: high/low
- Rationale: A plugin whose only side effects are console.log calls is a stub. High when there is no IO anywhere and >=3 logs; low for noisy logging.
- Failing example: `onClicked: console.log("toggled")`
- Fix: make each handler perform its action
- Checked by: usuba/checks.py

### USB-H04: No demo click handlers
- Level: high
- Rationale: A click handler whose only action is reporting the click (notify-send "Clicked", console.log) is a placeholder.
- Failing example: `onClicked: execDetached(["notify-send", "Clicked at"])`
- Fix: make the click do what the plugin is for
- Checked by: usuba/checks.py

### USB-H05: Not a placeholder UI
- Level: error
- Rationale: All UI handlers empty/no-op, handlers calling empty functions, or a trivial plugin with no IO/data/interaction.
- Failing example: `onClicked: {}`
- Fix: implement the behaviour
- Checked by: static_checks

### USB-H06: No placeholder data patterns
- Level: error
- Rationale: Lorem ipsum, Item 1/2/3, John Doe, random numbers presented as metrics.
- Failing example: `model: ["Item 1", "Item 2"]`
- Fix: use real data
- Checked by: static_checks

## Runtime

### USB-R01: Loads and registers in the real shell
- Level: error
- Rationale: The plugin must load, register and instantiate every entry point without QML errors.
- Failing example: `"Foo is not a type", "failed to load"`
- Fix: fix the reported QML error
- Checked by: runtime

### USB-R02: No runtime JS/QML errors
- Level: error
- Rationale: TypeError/ReferenceError/binding errors during startup and the interaction probe.
- Failing example: `TypeError: Cannot read property 'x' of undefined`
- Fix: guard the value or use the real API
- Checked by: runtime

### USB-R03: Visible, legible, on-screen
- Level: error
- Rationale: Bar widgets/panels must draw something visible, inside the screen, with legible contrast and non-zero size.
- Failing example: `zero-size bar widget`
- Fix: give the widget implicit size and theme colours
- Checked by: runtime

### USB-R04: Runtime commands are valid
- Level: error
- Rationale: Processes run during the probe must exist on the Dell and receive defined arguments; no writes outside the plugin's area.
- Failing example: `exec: walker does not exist on the Dell`
- Fix: use installed programs and defined args
- Checked by: runtime
