# dell-ref: provenance (audit F6)

- `omarchy-4.0.4/` is a capture of `/usr/share/omarchy` from the reference laptop (Dell) running the Arch package `omarchy 4.0.4-1` (`omarchy-4.0.4-pkgver.txt`). Images are excluded; absolute symlinks into `/usr/bin` are kept as-is and dangle off the device.
- **Version, settled:** the package on the Dell is `omarchy 4.0.4-1` (`omarchy-4.0.4-pkgver.txt`, the capture metadata). The tree's own `version` file reads `4.0.0.alpha` because upstream did not bump it in that tree; both strings describe the same capture, so `4.0.4-1` is the version to quote and `4.0.0.alpha` is only the file's content. The tree's `shell/` is byte-identical to basecamp/omarchy@`c668141e9c42b13c80c9ca4ea108e11708c5e8a5` (`functest/dell_env/setup.py` `OMARCHY_COMMIT`, which builds the runtime from that commit; checked there against `omarchy-shell-ref.tar.gz`). The commit for the package as a whole (outside `shell/`) is not recorded; no per-run record carries an Omarchy version field, so the run records cannot settle it either. When the package is rebuilt from a known tag, record the tag and the package sha256 here.
- `omarchy-4.0.4-tree.tar.gz` (sha256 `3105074581aee019357c1752a99556b9c9f3e0ed38c676780795ee29219b2373`) is **not** a byte-for-byte duplicate of the extracted tree: it additionally contains `default/plymouth/logos` (images). No code reads it. It is kept for that reason; delete it if the images are not wanted.
